## 一、数据库选型

本项目使用 **MySQL 8** 作为数据库。

**为什么选 MySQL？**
- 最流行的开源关系型数据库，资料多、社区活跃
- Spring Boot + JPA 对 MySQL 支持成熟
- 支持事务（保证数据一致性）
- Railway 等云平台提供一键部署

**字符集**：`utf8mb4_unicode_ci`
- `utf8mb4`：支持所有 Unicode 字符（包括 emoji）
- `unicode_ci`：排序规则，不区分大小写

## 三、核心表详解

### 3.1 sys_user（用户表）

存储所有注册用户的信息。

```sql
CREATE TABLE sys_user (
    id          BIGINT AUTO_INCREMENT PRIMARY KEY,
    username    VARCHAR(64)  NOT NULL UNIQUE,    -- 登录用的用户名
    email       VARCHAR(128) UNIQUE,              -- 邮箱（用于验证码登录）
    password_hash VARCHAR(128) NOT NULL,           -- 加密后的密码
    nickname    VARCHAR(64)  NOT NULL,             -- 显示昵称
    avatar      TEXT,                               -- 头像（base64 或 preset:xxx）
    role        VARCHAR(20)  NOT NULL,             -- USER 或 ADMIN
    status      VARCHAR(20)  NOT NULL,             -- ACTIVE 或 DISABLED
    created_at  DATETIME(6),                       -- 创建时间
    updated_at  DATETIME(6)                        -- 更新时间
);
```

**字段说明**：
- `password_hash` 不存明文密码，存的是 `SHA256(盐值+密码)` 的结果
- `avatar` 支持两种格式：`data:image/png;base64,...`（用户上传）或 `preset:gradient-1`（系统预设渐变色头像）
- `role` 默认 `USER`，管理员是 `ADMIN`
- `status` 默认 `ACTIVE`，管理员可以禁用用户

### 3.2 learning_material（学习资料表）

存储用户上传的每份学习资料。

```sql
CREATE TABLE learning_material (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY,
    owner_id        BIGINT        NOT NULL,        -- 谁上传的（sys_user.id）
    title           VARCHAR(128)  NOT NULL,         -- 资料标题
    source_type     VARCHAR(20)   NOT NULL,         -- PDF/DOCX/PPTX/TXT/MD/HTML/WEB
    original_name   VARCHAR(255)  NOT NULL,         -- 原始文件名
    storage_path    VARCHAR(512)  NOT NULL,         -- 文件存储路径（相对路径）
    source_url      VARCHAR(512),                   -- 来源URL（网页导入时）
    file_size       BIGINT        NOT NULL,         -- 文件大小（字节）
    parse_status    VARCHAR(20)   NOT NULL,         -- PENDING/PARSING/SUCCESS/FAILED
    summary_status  VARCHAR(20)   NOT NULL,         -- PENDING/SUCCESS/FAILED
    preview_status  VARCHAR(20)   NOT NULL,         -- NONE/READY/DEGRADED/FAILED
    preview_error   TEXT,                            -- 预览失败原因
    page_count      INT,                             -- 总页数（PDF/DOCX）
    chunk_count     INT          NOT NULL DEFAULT 0, -- 分块数量
    created_at      DATETIME(6),
    updated_at      DATETIME(6),
    INDEX idx_owner_created (owner_id, created_at)
);
```

**状态流转**：
```
上传 → PENDING → PARSING → SUCCESS（可以问答了）
                          → FAILED（解析失败）
```

### 3.3 material_chunk（资料分块表）

每份资料被拆分成多个文本块，这是 RAG 检索的基本单位。

```sql
CREATE TABLE material_chunk (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY,
    material_id     BIGINT        NOT NULL,        -- 属于哪份资料
    chunk_index     INT           NOT NULL,         -- 分块序号（从0开始）
    chunk_text      TEXT          NOT NULL,         -- 分块文本内容
    page_no         INT,                             -- 来源页码
    section_title   VARCHAR(255),                    -- 章节标题
    hierarchy_path  VARCHAR(500),                    -- 层级路径 "书名 > 章 > 节"
    summary         VARCHAR(500),                    -- 自动生成的摘要
    keywords        VARCHAR(500),                    -- 自动提取的关键词
    embedding_json  TEXT,                             -- 向量 Embedding（JSON 数组）
    created_at      DATETIME(6),
    UNIQUE KEY uk_material_chunk (material_id, chunk_index),
    INDEX idx_material_page (material_id, page_no)
);
```

**embedding_json 示例**：
```json
[0.0123, -0.0456, 0.0789, ..., 0.0321]
```
这是一个 1536 维的浮点数数组，代表这段文本的"语义向量"。两个向量越接近（余弦相似度越高），说明文本含义越相似。

**分块规则**：
- 最小 300 字符，最大 800 字符
- 相邻块之间有 100 字符重叠（防止语义被切断）
- 按段落拆分，超长段落按句子拆分

### 3.4 material_upload_session（上传会话表）

支持大文件分片上传（类似断点续传）。

```sql
CREATE TABLE material_upload_session (
    session_id       VARCHAR(64) PRIMARY KEY,       -- 会话ID（UUID）
    client_upload_id VARCHAR(64)  NOT NULL,         -- 客户端上传ID（防重复）
    owner_id         BIGINT       NOT NULL,
    title            VARCHAR(128) NOT NULL,
    source_type      VARCHAR(20)  NOT NULL,
    original_name    VARCHAR(255) NOT NULL,
    file_size        BIGINT       NOT NULL,
    chunk_size       INT          NOT NULL,          -- 每片大小（5MB）
    total_chunks     INT          NOT NULL,          -- 总片数
    uploaded_chunks  INT          NOT NULL DEFAULT 0,-- 已上传片数
    storage_path     VARCHAR(512) NOT NULL,
    checksum_sha256  VARCHAR(128),                   -- 文件校验和
    status           VARCHAR(20)  NOT NULL,          -- UPLOADING/PROCESSING/SUCCESS/FAILED
    material_id      BIGINT,                         -- 处理完成后关联的资料ID
    error_message    TEXT,
    UNIQUE KEY uk_owner_client (owner_id, client_upload_id)
);
```

**上传流程**：
```
1. 前端创建会话 → 记录元数据
2. 前端逐片上传 → 每片写入临时文件
3. 所有片上传完成 → 后端合并文件 → 解析 → 分块 → Embedding
4. 状态变为 SUCCESS
```

### 3.6 rag_question（问答记录表）

```sql
CREATE TABLE rag_question (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY,
    user_id         BIGINT        NOT NULL,
    conversation_id BIGINT,                           -- 对话ID（同一组对话共享）
    question_text   TEXT          NOT NULL,            -- 用户问题
    title           TEXT,                              -- 对话标题（自动截取）
    pinned          BIT NOT NULL DEFAULT FALSE,        -- 是否置顶
    answer_text     TEXT          NOT NULL,            -- AI 回答
    model_name      VARCHAR(64)   NOT NULL,            -- 使用的模型
    question_status VARCHAR(20)   NOT NULL,            -- INIT/RUNNING/SUCCESS/FAILED
    created_at      DATETIME(6),
    updated_at      DATETIME(6),
    INDEX idx_user_conv_created (user_id, conversation_id, created_at)
);
```

**conversation_id 的作用**：把多轮问答归为一组。第一个问题的 `conversation_id` 等于自己的 `id`，后续问题引用这个 `id`。

## 五、Flyway 数据库迁移

### 什么是 Flyway？

Flyway 是一个数据库版本管理工具。它通过 SQL 脚本来管理数据库的变更，类似于 Git 管理代码。

**为什么不用 JPA 自动生成表？**
- JPA 的 `ddl-auto: update` 只能加字段、加表，不能删字段、改类型
- Flyway 可以执行任意 SQL，更适合生产环境
- 多人协作时，Flyway 保证每个人数据库结构一致

### 迁移文件

本项目只有一个迁移文件：`V1__baseline_schema.sql`

文件名格式：`V{版本号}__{描述}.sql`

```
V1__baseline_schema.sql    ← 创建所有 14 张表
V2__add_xxx.sql            ← 未来新增的迁移（按需添加）
```

Flyway 会在数据库中创建一张 `flyway_schema_history` 表，记录哪些迁移已经执行过。

### 如何新增迁移

1. 在 `src/main/resources/db/migration/` 下新建 SQL 文件
2. 文件名以 `V2__` 开头（版本号递增）
3. 写 ALTER TABLE 或其他 SQL
4. 重启应用，Flyway 自动执行

## 六、JPA 实体映射

### 什么是 JPA？

JPA（Java Persistence API）是 Java 的数据库操作标准。它可以把 Java 对象自动映射到数据库表，你写 Java 代码就能操作数据库，不用写 SQL。

### 实体类示例

```java
@Entity                           // 声明这是一个 JPA 实体
@Table(name = "sys_user")         // 对应数据库中的 sys_user 表
public class UserEntity {

    @Id                           // 主键
    @GeneratedValue(strategy = GenerationType.IDENTITY)  // 自增
    private Long id;

    @Column(nullable = false, unique = true, length = 64)
    private String username;

    @Column(length = 128, unique = true)
    private String email;

    @Column(name = "password_hash", nullable = false, length = 128)
    private String passwordHash;

    @Column(nullable = false, length = 64)
    private String nickname;

    @Column(columnDefinition = "TEXT")
    private String avatar;

    @Column(nullable = false, length = 20)
    private String role = "USER";   // 默认值

    @Column(nullable = false, length = 20)
    private String status = "ACTIVE";

    @Column(name = "created_at")
    private LocalDateTime createdAt;

    @Column(name = "updated_at")
    private LocalDateTime updatedAt;

    @PrePersist                       // 插入前自动执行
    protected void onCreate() {
        createdAt = LocalDateTime.now();
        updatedAt = LocalDateTime.now();
    }

    @PreUpdate                        // 更新前自动执行
    protected void onUpdate() {
        updatedAt = LocalDateTime.now();
    }
}
```

### Repository 接口

```java
public interface UserRepository extends JpaRepository<UserEntity, Long> {
    // Spring Data JPA 自动根据方法名生成 SQL
    Optional<UserEntity> findByUsername(String username);
    Optional<UserEntity> findByEmail(String email);
    boolean existsByUsername(String username);
    List<UserEntity> findAllByOrderByCreatedAtDesc();
}
```

**JpaRepository 提供的内置方法**：
- `save(entity)` — 保存（新增或更新）
- `findById(id)` — 按 ID 查询
- `findAll()` — 查询所有
- `deleteById(id)` — 按 ID 删除
- `count()` — 计数

### 为什么不用外键关联？

本项目所有的关联都是"逻辑关联"——只存 ID，不加 `@ManyToOne` / `@OneToMany` 注解和数据库外键。

```java
// 本项目的做法（逻辑关联）
@Column(name = "owner_id", nullable = false)
private Long ownerId;

// 如果用外键关联（JPA 关联）
// @ManyToOne
// @JoinColumn(name = "owner_id")
// private UserEntity owner;
```

**原因**：
- 避免 JPA 懒加载/急加载的各种坑
- 删除数据时不用处理级联
- 更灵活，可以在不加载关联实体的情况下做查询

## 七、索引设计

### 什么是索引？

索引就像书的目录——没有目录，找内容要从头翻到尾；有目录，直接翻到对应页。数据库索引让查询更快。

### 本项目的关键索引

| 表 | 索引名 | 列 | 用途 |
|----|--------|-----|------|
| `learning_material` | `idx_owner_created` | `(owner_id, created_at)` | 查询某用户的资料，按时间排序 |
| `material_chunk` | `uk_material_chunk` | `(material_id, chunk_index)` | 保证同一资料的分块序号唯一 |
| `material_chunk` | `idx_material_page` | `(material_id, page_no)` | 查询某页的所有分块 |
| `rag_question` | `idx_user_conv_created` | `(user_id, conversation_id, created_at)` | 查询某用户某对话的所有问答 |
| `rag_question_source` | `idx_question_score` | `(question_id, rank_score)` | 查询某问题的来源，按分数排序 |
| `user_favorite` | `uk_user_question` | `(user_id, question_id)` | 保证同一用户不能重复收藏同一问答 |
| `rag_evaluation_suite` | `idx_scheduled_next` | `(scheduled, next_run_at)` | 定时评估调度器查询待执行的套件 |

**什么时候需要加索引？**
- 经常用于 WHERE 条件的列
- 经常用于 JOIN 的列
- 经常用于 ORDER BY 的列
- 需要唯一约束的列组合

### 8.1 LearningMaterialEntity — 学习资料实体

```java
package com.mytext.learningassistant.material;

import java.time.LocalDateTime;
import jakarta.persistence.*;

@Entity
@Table(name = "learning_material")
public class LearningMaterialEntity {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(name = "owner_id", nullable = false)
    private Long ownerId;

    @Column(nullable = false, length = 128)
    private String title;

    @Enumerated(EnumType.STRING)
    @Column(name = "source_type", nullable = false, length = 20)
    private MaterialSourceType sourceType;

    @Column(name = "original_name", nullable = false, length = 255)
    private String originalName;

    @Column(name = "storage_path", nullable = false, length = 512)
    private String storagePath;

    @Column(name = "source_url", length = 512)
    private String sourceUrl;

    @Column(name = "file_size", nullable = false)
    private Long fileSize;

    @Enumerated(EnumType.STRING)
    @Column(name = "parse_status", nullable = false, length = 20)
    private MaterialParseStatus parseStatus;

    @Enumerated(EnumType.STRING)
    @Column(name = "summary_status", nullable = false, length = 20)
    private MaterialSummaryStatus summaryStatus;

    @Enumerated(EnumType.STRING)
    @Column(name = "preview_status", nullable = false, length = 20)
    private MaterialPreviewStatus previewStatus;

    @Column(name = "preview_error", columnDefinition = "TEXT")
    private String previewError;

    @Column(name = "page_count")
    private Integer pageCount;

    @Column(name = "chunk_count", nullable = false)
    private Integer chunkCount = 0;

    @Column(name = "created_at", nullable = false)
    private LocalDateTime createdAt;

    @Column(name = "updated_at", nullable = false)
    private LocalDateTime updatedAt;

    @PrePersist
    void onCreate() {
        LocalDateTime now = LocalDateTime.now();
        if (createdAt == null) createdAt = now;
        updatedAt = now;
        if (parseStatus == null) parseStatus = MaterialParseStatus.PENDING;
        if (summaryStatus == null) summaryStatus = MaterialSummaryStatus.PENDING;
        if (previewStatus == null) previewStatus = MaterialPreviewStatus.NONE;
        if (chunkCount == null) chunkCount = 0;
    }

    @PreUpdate
    void onUpdate() { updatedAt = LocalDateTime.now(); }

    // Getter 和 Setter 省略（实际代码中需要完整提供）
}
```

**枚举类型**：
- `MaterialSourceType`：`PDF`, `DOCX`, `PPTX`, `TXT`, `MD`, `HTML`, `WEB`
- `MaterialParseStatus`：`PENDING`, `PARSING`, `SUCCESS`, `FAILED`
- `MaterialSummaryStatus`：`PENDING`, `SUCCESS`, `FAILED`
- `MaterialPreviewStatus`：`NONE`, `READY`, `DEGRADED`, `FAILED`
