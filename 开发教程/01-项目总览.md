## 一、这个项目是什么？

### 一句话概括

**课程学习助手**是一个"给 AI 喂你的学习资料，然后你可以随时问它问题"的网站。

### 通俗解释

想象一下：你有一门课，老师发了几十页 PDF 讲义、几份 Word 文档、一堆 PPT。你想复习，但翻来翻去太累了。

这个项目做的事情是：

1. **上传资料** — 你把 PDF、Word、PPT、纯文本等文件上传到网站。
2. **AI 阅读资料** — 网站会自动"阅读"这些文件，把内容拆成小段并理解语义。
3. **你问，AI 答** — 你输入问题（比如"第三章讲了什么？"），AI 会从你上传的资料中找到相关内容，然后用自然语言回答你，并告诉你答案出自哪份资料的哪一页。

这个过程在技术上有一个专门的名字，叫做 **RAG（Retrieval-Augmented Generation，检索增强生成）**。

> **什么是 RAG？**
>
> 简单来说就是：先"检索"（从你的资料中找到最相关的内容），再"生成"（让 AI 根据找到的内容写出回答）。这样 AI 的回答就有了依据，不会凭空编造。

### 打个比方

| 比喻 | 对应系统中的角色 |
|------|-----------------|
| 你把课本和笔记交给学霸 | 上传学习资料 |
| 学霸把每一页内容做成索引卡片 | 文档解析与向量化（拆分成小段、转化为数字向量） |
| 你问学霸一个问题 | 用户提问 |
| 学霸翻出最相关的几张卡片 | 语义检索 |
| 学霸根据卡片内容组织语言回答你 | 大语言模型生成回答 |

## 二、技术栈全景图

### 2.1 后端技术

| 技术 | 版本 | 通俗解释 | 为什么选它 |
|------|------|---------|-----------|
| **Java** | 21 | 编程语言，后端代码的"母语" | 企业级应用最广泛的语言，稳定可靠 |
| **Spring Boot** | 3.5.6 | Java 的 Web 开发框架，帮你处理底层细节 | 生态成熟、文档丰富、社区活跃 |
| **MySQL** | 8 | 关系型数据库，用表格存储数据 | 免费、稳定、性能好，云平台普遍支持 |
| **Flyway** | - | 数据库版本管理工具，用 SQL 脚本管理表结构变更 | 避免团队协作时数据库结构不一致 |
| **JPA/Hibernate** | - | 数据库 ORM，用 Java 对象操作数据库，不用写 SQL | 简化数据库操作 |
| **Apache PDFBox** | 3.0.5 | PDF 文件处理库，从 PDF 提取文字 | 功能强大、开源免费 |
| **Jackson** | - | JSON 处理库，Java 对象和 JSON 互相转换 | Spring Boot 默认集成 |
| **Maven** | (via mvnw) | Java 的包管理工具，类似前端的 npm | 自动下载依赖，构建项目 |

| 技术 | 版本 | 通俗解释 | 为什么选它 |

| **React** | 18.3 | 前端 UI 框架，用"组件"方式构建页面 | 组件化开发、生态丰富 |

| **React Router** | 6.28 | 页面路由管理，控制页面跳转 | SPA 标准路由方案 |
| **TanStack Query** | 5.62 | 服务端数据管理（请求、缓存、加载状态） | 简化数据交互 |
| **Axios** | - | HTTP 客户端，前端向后端发请求 | 比 fetch 更易用 |
| **react-hook-form + Zod** | - | 表单管理和验证 | 简化表单验证 |
| **Framer Motion** | - | 动画库，添加过渡效果 | 提升用户体验 |
| **Lucide React** | - | 图标库 | 精美的 SVG 图标 |

### 2.3 AI 相关技术

| 技术 | 通俗解释 |
|------|---------|
| **大语言模型（LLM）** | 理解问题并生成回答的 AI 模型，支持 OpenAI Chat Completions 和 Responses API 两种格式 |
| **Embedding 模型** | 把文字转换成数字向量（比如每段文字变成 1536 个数字），语义相近的文字，这些数字也相近 |
| **Reranker** | 对检索结果二次排序，把最相关的排到前面 |
| **Qdrant（可选）** | 专门存储和搜索向量的数据库，比 MySQL 暴力搜索快得多 |

### 2.4 部署技术

| 技术 | 通俗解释 |
|------|---------|
| **Docker** | 容器化技术，把程序和依赖打包成"容器"，在任何地方都能运行 |
| **Docker Compose** | 一键编排多个容器（MySQL + Backend + Nginx） |
| **阿里云轻量服务器** | 24 小时在线的云服务器，运行 Docker 容器 |
| **Nginx** | 高性能 Web 服务器，托管前端文件并转发 API 请求 |
| **MobaXterm** | Windows 上的 SSH/SFTP 工具，连接服务器和上传文件 |

## 三、项目功能详解

### 3.1 用户注册与登录

| 方式 | 说明 |
|------|------|
| 用户名 + 密码 | 传统登录方式 |
| 邮箱 + 验证码 | 输入邮箱，系统发验证码邮件（支持 QQ/163 邮箱通道） |

第一个注册的用户自动成为普通用户。默认管理员账号 `admin` / `12345678`。

### 3.2 学习资料上传与管理

- 支持 PDF、DOCX（Word）、PPTX（PowerPoint）、TXT、Markdown、HTML
- 单个文件最大 500MB，大文件自动分片上传（每片 5MB，支持断点续传）
- 支持输入网页链接直接导入
- 上传后自动提取文字、分块、生成向量
- PDF 大文件（>64MB）自动用 Ghostscript 压缩
- 支持 OCR 识别扫描件中的文字

### 3.3 RAG 智能问答（核心功能）

```
用户提问 → 查询扩展 → 混合检索（向量+BM25+关键词）→ 重排序 → LLM生成回答 → 流式输出
```

- **通用模式**：直接问 AI，不绑定资料
- **资料模式**：从上传的资料中检索相关内容，AI 基于资料回答
- 回答中标注引用来源（资料名 + 页码）
- 支持多轮对话（记住上下文）
- 图片问答：支持上传图片或粘贴图片，后端按多模态请求发送给模型

### 3.4 用户自定义大模型配置

用户可以保存多套自定义模型配置：
- 设置 API 地址、API Key、模型名称
- 选择 API 格式（Chat Completions 或 Responses）
- 测试连接是否正常
- 在多个配置之间切换
- API Key 加密存储，前端只显示是否已配置

### 3.5 文档阅读器

三栏布局：左侧目录导航 + 中间页面预览 + 右侧 AI 问答。选中文字可直接提问。

### 3.6 其他功能

- 摘要生成：AI 自动总结资料要点
- 问答历史：自动保存，支持搜索、收藏、置顶
- RAG 评估：批量测试问答质量，支持定时回归运行
- 管理后台：用户管理、资料管理、系统日志、使用记录
- 使用记录：管理员可查看用户问答、资料上传等操作记录、模型名称和 token 消耗
- 深色模式：亮色/暗色主题切换
- 全局搜索：Ctrl+K 快捷搜索

### 配置

本地配置存储在 `backend/.env` 和 `backend/.env.local`（后者覆盖前者）。关键配置包括：

```env
SPRING_PROFILES_ACTIVE=prod
MYSQL_URL=jdbc:mysql://127.0.0.1:3306/learning_assistant?...
MYSQL_USERNAME=root
MYSQL_PASSWORD=<你的密码>
APP_AUTH_SECRET=<随机字符串>
APP_STORAGE_DIR=./data/learning-assistant-files
LLM_ENABLED=true
LLM_BASE_URL=<API地址>
LLM_API_KEY=<API密钥>
LLM_MODEL=<模型名>
LLM_API_FORMAT=responses
```

**LLM_API_FORMAT 说明**：

| 值 | 含义 |
|----|------|
| `chat-completions` | OpenAI Chat Completions 兼容接口（`/v1/chat/completions`） |
| `responses` | OpenAI Responses API 兼容接口（`/v1/responses`） |
