# 智学引擎 — 项目开发完全指南（六）：部署上线

> 本文档教你如何把项目部署到阿里云轻量应用服务器上，使用 Docker Compose 编排所有服务，让任何人都能通过公网访问。

---

## 一、部署架构总览

本项目使用**阿里云轻量应用服务器 + Docker Compose + Nginx**方案。

### 1.1 整体架构图

```
用户浏览器
   │
   ▼
阿里云轻量应用服务器 (公网 IP)
   │
   ├── Nginx (端口 80)
   │   ├── /          → 前端静态文件 (/opt/learning-assistant/frontend-dist)
   │   └── /api/*     → 反向代理到后端 (http://backend:8080)
   │
   └── Docker Compose (3 个容器在同一网络)
       ├── mysql      → MySQL 8 数据库 (数据卷: mysql-data)
       ├── redis      → Redis 7 缓存（可选，用于限流状态共享）
       ├── backend    → Spring Boot 后端容器 (文件存: app-data)
       └── nginx      → 前端静态资源 + /api 反向代理
```

### 1.2 各组件职责

| 组件 | 作用 | 通俗解释 |
|------|------|---------|
| **阿里云轻量服务器** | 一台 24 小时在线的云电脑 | 项目的"家" |
| **Docker Compose** | 一键启动/停止/更新所有服务 | 项目的"遥控器" |
| **MySQL 容器** | 存储用户、资料、问答等数据 | 项目的"记忆" |
| **Redis 容器**（可选） | 存储限流状态，多实例共享 | 项目的"短期记忆" |
| **Backend 容器** | 运行 Spring Boot 后端程序 | 项目的"大脑" |
| **Nginx 容器** | 托管前端页面 + 转发 API 请求 | 项目的"门面" |
| **MobaXterm** | 本地向服务器上传文件的工具 | 项目的"快递员" |

### 1.3 为什么不用 Railway + Vercel 了？

最初版本部署在 Railway（后端）+ Vercel（前端）上。后来迁移到了阿里云，原因：
- 阿里云服务器在国内访问更快（低延迟）
- Docker Compose 可以一键管理所有服务，不依赖外部平台
- 数据完全在自己手里，不受第三方平台限制
- 月费固定，不按使用量计费

## 二、服务器初始配置

### 2.1 购买阿里云轻量应用服务器

1. 访问 [aliyun.com](https://www.aliyun.com)，搜索"轻量应用服务器"
2. 选择配置（推荐 2 核 2G 以上）
3. 地域选择靠近用户的区域（中国大陆选华东/华北）
4. 镜像选择 **Ubuntu 22.04**（或 24.04）
5. 购买后获取**公网 IP** 和 **root 密码**

### 2.2 连接到服务器

使用 SSH 工具连接服务器。真实服务器密钥只保存在本地，不要提交到 GitHub。

**方式一：使用 MobaXterm**（推荐给新手）：
1. 打开 MobaXterm，点击 Session → SSH
2. Remote host 填入公网 IP
3. 如果服务器使用密钥登录，勾选 "Use private key"，选择你本地保存的密钥文件
4. 连接成功后进入命令行

**方式二：使用命令行**：
```bash
ssh root@<你的公网IP>
# 输入密码登录
```

### 2.3 安装 Docker

连接到服务器后，逐行执行以下命令：

```bash
# 更新软件包列表
apt update

# 安装 Docker
apt install -y docker.io

# 安装 Docker Compose（独立版）
apt install -y docker-compose-v2

# 验证安装
docker --version
docker compose version

# 设置 Docker 开机自启
systemctl enable docker
systemctl start docker
```

### 2.4 创建项目目录结构

在服务器上创建以下目录：

```bash
mkdir -p /opt/learning-assistant/repo/backend
mkdir -p /opt/learning-assistant/repo/frontend
mkdir -p /opt/learning-assistant/frontend-dist
mkdir -p /opt/learning-assistant/mysql-data
mkdir -p /opt/learning-assistant/app-data
mkdir -p /opt/learning-assistant/nginx
```

目录说明：

| 目录 | 用途 |
|------|------|
| `/opt/learning-assistant/repo/backend` | 后端代码和 Dockerfile |
| `/opt/learning-assistant/repo/frontend` | 前端源代码 |
| `/opt/learning-assistant/frontend-dist` | 前端构建产物（npm run build 输出） |
| `/opt/learning-assistant/mysql-data` | MySQL 数据持久化（容器重启数据不丢失） |
| `/opt/learning-assistant/app-data` | 用户上传的文件（PDF、图片等） |
| `/opt/learning-assistant/nginx` | Nginx 配置文件 |

### 2.5 配置防火墙

在阿里云控制台开放端口：
1. 进入轻量应用服务器 → 防火墙
2. 添加规则：开放 **80 端口**（HTTP）
3. 如果需要 HTTPS，也开放 **443 端口**

> 不要开放 3306（MySQL）和 8080（后端）端口！这些只在 Docker 内网通信，对外暴露有安全风险。

## 三、准备部署文件

当前仓库不维护 `upload-package/` 中间目录。后端部署使用 `backend/` 目录中的 Dockerfile、源码和 Maven 配置；前端静态资源由 `deploy/deploy-frontend.ps1` 在本地构建、打包并上传到服务器。

### 3.1 本地→服务器文件路径对照

> 💡 下表列出部署涉及的所有文件在本地和服务器上的对应位置。

| 文件 | 本地路径 | 服务器路径 |
|------|---------|-----------|
| **后端 Dockerfile** | `backend/Dockerfile` | `/opt/learning-assistant/repo/backend/Dockerfile` |
| **后端源码** | `backend/src/` | `/opt/learning-assistant/repo/backend/src/` |
| **后端 pom.xml** | `backend/pom.xml` | `/opt/learning-assistant/repo/backend/pom.xml` |
| **后端 Maven Wrapper** | `backend/mvnw` `backend/mvnw.cmd` | `/opt/learning-assistant/repo/backend/mvnw` |
| **后端环境变量模板** | `backend/.env.example` | `/opt/learning-assistant/repo/backend/.env.example` |
| **前端源码** | `frontend/src/` | `/opt/learning-assistant/repo/frontend/src/` |
| **前端 package.json** | `frontend/package.json` | `/opt/learning-assistant/repo/frontend/package.json` |
| **前端构建产物** | `frontend/dist/`（npm run build 输出） | `/opt/learning-assistant/frontend-dist/` |
| **前端部署脚本** | `deploy/deploy-frontend.ps1` | 本地执行，不上传到服务器 |
| **Nginx 配置模板** | `deploy/nginx-default.conf` | `/opt/learning-assistant/nginx/nginx.conf` |
| **环境变量模板** | `deploy/server.env.example` | `/opt/learning-assistant/.env` |
| **Docker Compose** | 服务器上创建或按部署环境维护 | `/opt/learning-assistant/docker-compose.yml` |
| **MySQL 数据** | （自动生成） | `/opt/learning-assistant/mysql-data/` |
| **用户上传文件** | （自动生成） | `/opt/learning-assistant/app-data/` |

### 3.2 deploy 目录内容

```
deploy/
├── deploy-frontend.ps1     # 构建 frontend/dist 并安全替换服务器 frontend-dist 内容
├── nginx-default.conf      # Nginx 反向代理和前端静态资源配置模板
└── server.env.example      # 服务器 .env 模板
```

后端部署所需文件仍在 `backend/` 目录中：`Dockerfile`、`pom.xml`、`mvnw`、`.env.example` 和 `src/`。

### 3.3 构建并部署前端

推荐使用仓库内的安全部署脚本，它会保留服务器上的 `frontend-dist` 目录本身，只替换目录内容，避免 Docker bind mount 失效：

```powershell
cd C:\你的路径\learning-assistant
.\deploy\deploy-frontend.ps1 -Server "root@你的服务器公网IP" -SshKey "C:\你的路径\your-server-key.pem" -RemoteAppDir "/opt/learning-assistant" -ApiBase "/api"
```

脚本内部会执行 `npm run build`，检查生产包中是否误包含 `localhost:8080`，再通过 `scp` 上传压缩包并在服务器端替换静态文件。

### 3.4 什么是 Dockerfile？

Dockerfile 就像一份"做菜食谱"，告诉 Docker 如何构建一个容器镜像。

后端 Dockerfile 的关键内容：

```dockerfile
# 第一阶段：编译 Java 项目
FROM eclipse-temurin:21-jdk-jammy AS builder
WORKDIR /workspace
COPY . .
RUN ./mvnw -q -DskipTests clean package

# 第二阶段：运行时（只包含 JRE，更小）
FROM eclipse-temurin:21-jre-jammy
RUN apt-get update && apt-get install -y \
    ghostscript \              # PDF 压缩
    libreoffice \              # Office 文档转 PDF
    tesseract-ocr \            # OCR 文字识别
    tesseract-ocr-chi-sim \    # 中文 OCR 语言包
    fonts-noto-cjk \           # 中文字体
    && rm -rf /var/lib/apt/lists/*
COPY --from=builder /workspace/app.jar /app/app.jar
ENV SPRING_PROFILES_ACTIVE=prod
ENV APP_STORAGE_DIR=/data/learning-assistant-files
EXPOSE 8080
```

> **两阶段构建的好处**：编译工具（JDK、Maven）加起来几百 MB，但运行时不需要。最终镜像只包含 JRE + 系统工具，体积小很多。

## 四、上传文件到服务器

后端和前端的部署方式不同：后端需要上传源码并重新构建 Docker 镜像；前端是静态资源，推荐使用 `deploy/deploy-frontend.ps1` 构建并安全替换服务器目录内容。

### 4.1 上传后端代码

1. 在 MobaXterm 中连接到服务器。
2. 左侧会显示本地文件浏览器和远程文件浏览器。
3. 将本地 `backend/` 目录下的 `Dockerfile`、`pom.xml`、`mvnw`、`.mvn/`、`src/`、`.env.example` 等部署所需文件上传到远程的 `/opt/learning-assistant/repo/backend/`。

> 不要上传 `backend/target/`、`backend/data/`、`backend/.m2/` 这类本地生成目录。

### 4.2 部署前端静态资源

在本地 Windows PowerShell 执行：

```powershell
cd C:\你的路径\learning-assistant
.\deploy\deploy-frontend.ps1 -Server "root@你的服务器公网IP" -SshKey "C:\你的路径\your-server-key.pem" -RemoteAppDir "/opt/learning-assistant" -ApiBase "/api"
```

这个脚本会构建 `frontend/dist/`、上传压缩包，并在服务器上只替换 `/opt/learning-assistant/frontend-dist/` 的目录内容。

### 4.3 验证上传结果

在服务器上检查：

```bash
# 检查后端文件
ls /opt/learning-assistant/repo/backend/
# 应该看到：Dockerfile pom.xml mvnw src/ .env.example ...

# 检查前端构建产物
ls /opt/learning-assistant/frontend-dist/
# 应该看到：index.html assets/ ...
```

### 5.1 docker-compose.yml

在服务器上创建 `/opt/learning-assistant/docker-compose.yml`：

```bash
cat > /opt/learning-assistant/docker-compose.yml << 'DOCKEREOF'
version: "3.8"

services:
  mysql:
    image: mysql:8.0
    container_name: la-mysql
    restart: unless-stopped
    environment:
      MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD}
      MYSQL_DATABASE: learning_assistant
      MYSQL_CHARSET: utf8mb4
      MYSQL_COLLATION: utf8mb4_unicode_ci
    volumes:
      - ./mysql-data:/var/lib/mysql
    ports:
      - "127.0.0.1:3306:3306"   # 只监听本地，不对外暴露

      - PDF_COMPRESSION_ENABLED=${PDF_COMPRESSION_ENABLED:-true}

      - RERANKER_ENABLED=${RERANKER_ENABLED:-true}
      - VECTOR_STORE_ENABLED=${VECTOR_STORE_ENABLED:-false}
      - APP_REDIS_ENABLED=${APP_REDIS_ENABLED:-false}
      - REDIS_HOST=${REDIS_HOST:-redis}
      - REDIS_PORT=${REDIS_PORT:-6379}
      - REDIS_PASSWORD=${REDIS_PASSWORD:-}
    volumes:
      - ./app-data:/data/learning-assistant-files
    depends_on:
      mysql:
        condition: service_healthy
      redis:
        condition: service_healthy
    ports:
      - "127.0.0.1:8080:8080"   # 只监听本地，由 Nginx 转发

  nginx:
    image: nginx:stable-alpine
    container_name: la-nginx
    restart: unless-stopped
    volumes:
      - ./frontend-dist:/usr/share/nginx/html:ro

    ports:

    depends_on:

```

> **关键配置说明**：
> - `MYSQL_URL` 中使用 `mysql:3306`（容器服务名），不是 `127.0.0.1`
> - `REDIS_HOST` 默认为 `redis`（Docker 服务名），本地开发时改为 `localhost`
> - `127.0.0.1:3306:3306` 和 `127.0.0.1:8080:8080` 和 `127.0.0.1:6379:6379` 保证数据库、后端和 Redis 不对外暴露
> - `depends_on` + `healthcheck` 确保 MySQL 和 Redis 启动完成后才启动后端
> - `volumes` 挂载实现数据持久化

### 5.2 Nginx 配置

在服务器上创建 `/opt/learning-assistant/nginx/nginx.conf`：

```bash
cat > /opt/learning-assistant/nginx/nginx.conf << 'NGINXEOF'
server {
    listen 80;
    server_name _;

    # 上传文件大小限制
    client_max_body_size 500m;

    # 前端静态文件
    location / {
        root /usr/share/nginx/html;
        index index.html;
        # SPA 路由支持：找不到文件时返回 index.html
        try_files $uri $uri/ /index.html;
    }

    # API 反向代理到后端
    location /api/ {
        proxy_pass http://backend:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # SSE 流式输出支持（AI 打字机效果）
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 120s;
        proxy_send_timeout 120s;
    }
}
NGINXEOF
```

> **重要配置**：
> - `try_files $uri $uri/ /index.html` — 解决刷新页面 404 问题（SPA 路由）
> - `proxy_buffering off` — 关闭缓冲，否则 AI 回答会等全部生成完才显示
> - `proxy_read_timeout 120s` — 120 秒超时，避免长回答被截断
> - `client_max_body_size 500m` — 允许上传大文件

**如何生成 `APP_AUTH_SECRET`？**

```bash
# 在服务器上执行
openssl rand -hex 32
```

**QQ 邮箱授权码获取步骤**：
1. 登录 QQ 邮箱网页版
2. 设置 → 账户 → POP3/IMAP/SMTP 服务
3. 开启 SMTP 服务，按提示发送短信
4. 获取到的 16 位授权码就是 `EMAIL_CODE_QQ_PASSWORD`

## 六、首次部署

### 6.1 启动所有服务

### 8.2.2 使用 SSH/SCP 上传到腾讯云

Windows PowerShell 可以直接使用 OpenSSH：

```powershell
$key = "C:\你的本地路径\your-server-key.pem"
$host = "root@你的服务器公网IP"

# 创建远程目录
ssh -i $key $host "mkdir -p /opt/learning-assistant/repo/backend /opt/learning-assistant/frontend-dist"

# 上传后端源码和配置
scp -i $key -r C:\你的路径\learning-assistant\backend\Dockerfile "${host}:/opt/learning-assistant/repo/backend/"
scp -i $key -r C:\你的路径\learning-assistant\backend\pom.xml "${host}:/opt/learning-assistant/repo/backend/"
scp -i $key -r C:\你的路径\learning-assistant\backend\mvnw "${host}:/opt/learning-assistant/repo/backend/"
scp -i $key -r C:\你的路径\learning-assistant\backend\.mvn "${host}:/opt/learning-assistant/repo/backend/"
scp -i $key -r C:\你的路径\learning-assistant\backend\src "${host}:/opt/learning-assistant/repo/backend/"
scp -i $key -r C:\你的路径\learning-assistant\backend\.env.example "${host}:/opt/learning-assistant/repo/backend/"

# 前端请优先在本地运行 deploy/deploy-frontend.ps1，它会构建、上传并安全替换 frontend-dist。

# 远程重建并启动服务
ssh -i $key $host "cd /opt/learning-assistant && docker compose stop backend nginx && docker compose up -d --build backend && docker compose up -d nginx && docker compose ps"
```

注意：`scp` 不会自动删除服务器上已经不存在于本地的旧文件。如果删除过后端源码目录中的文件，上传前应在服务器上清理对应目录，保留 `.env`、`mysql-data`、`app-data`。前端静态资源不要用 `rm -rf frontend-dist && mkdir frontend-dist` 的方式替换，应该使用 `deploy-frontend.ps1` 的“保留目录、替换内容”流程。

## 十、常见问题排查

### Q1：容器启动失败

**症状**：`docker compose up` 后容器反复重启。

**排查步骤**：
```bash
# 查看具体错误
docker compose logs backend
# 常见原因：环境变量未设置、MySQL 连接失败、端口占用
```

### Q2：MySQL 连接失败

**症状**：后端日志显示 `Communications link failure`。

**原因**：`MYSQL_URL` 写错了。

**解决**：Docker Compose 环境中，数据库地址必须是**容器服务名** `mysql`，不能写 `127.0.0.1`：
```env
MYSQL_URL=jdbc:mysql://mysql:3306/learning_assistant?useUnicode=true&...
```

### Q3：刷新页面显示 404

**症状**：登录后刷新 `/workspace/chat` 等页面出现 404。

**原因**：Nginx 没有配置 SPA 路由重写。

**解决**：确认 `nginx.conf` 中有：
```nginx
location / {
    try_files $uri $uri/ /index.html;
}
```

### Q4：文件上传后丢失

**症状**：上传的资料文件在容器重启后消失。

**原因**：没有挂载持久化数据卷，文件存在容器内部。

**解决**：确认 `docker-compose.yml` 中配置了 volumes：
```yaml
volumes:
  - ./app-data:/data/learning-assistant-files
```

### Q5：AI 回答不流式输出

**症状**：AI 回答不是逐字出现，而是等全部完成后一次性显示。

**原因**：Nginx 开启了响应缓冲。

**解决**：在 Nginx 配置的 `/api/` location 中添加：
```nginx
proxy_buffering off;
proxy_cache off;
```

### Q6：CORS 跨域错误

**症状**：浏览器控制台显示 `Access-Control-Allow-Origin` 错误。

**解决**：
1. 确认 `.env` 中 `APP_CORS_ALLOWED_ORIGINS` 包含当前访问的域名
2. 注意协议（http vs https）和端口
3. 修改后需要重启后端：`docker compose restart backend`

### Q7：邮箱验证码收不到

**排查**：
1. 检查垃圾邮件文件夹
2. 确认 SMTP 授权码正确（不是邮箱登录密码）
3. QQ 邮箱：设置 → 账户 → POP3/IMAP/SMTP → 生成授权码
4. 确认 `EMAIL_CODE_ENABLED=true`

### Q8：Docker 构建太慢

**原因**：首次构建需要下载 Java、Maven 依赖、LibreOffice 等。

**解决**：
- 首次构建 5-10 分钟是正常的
- 后续构建会使用 Docker 缓存，通常 1-3 分钟
- 如果只改 Java 代码不改 Dockerfile，构建很快

### Q9：端口被占用

**症状**：`bind: address already in use`。

**解决**：
```bash
# 查看占用 80 端口的进程
lsof -i :80

# 如果之前有其他 Nginx/Apache 在运行，先停止
systemctl stop nginx
systemctl stop apache2
```

### Q10：LLM 对话不工作

**症状**：发送消息后无响应或报错。

**排查**：
1. 确认 `LLM_ENABLED=true`
2. 检查 `LLM_BASE_URL` 和 `LLM_API_KEY`
3. 确认 `LLM_API_FORMAT` 与 API 提供商兼容
4. API 额度是否充足

### Q11：Redis 连接失败

**症状**：后端日志显示 `Connection refused` 或 `Unable to connect to Redis`。

**排查**：
1. 确认 Redis 容器已启动：`docker compose ps`
2. 确认 `REDIS_HOST=redis`（Docker 服务名），不是 `localhost`
3. 如果设置了密码，确认 `REDIS_PASSWORD` 与 Docker Compose 中的 `--requirepass` 一致
4. 查看 Redis 容器日志：`docker compose logs redis`

**临时方案**：如果不需要 Redis，设置 `APP_REDIS_ENABLED=false` 即可，限流功能会使用内存存储。

### Q12：限流不生效或多实例限流不准

**症状**：多实例部署时，用户请求被分发到不同实例，限流计数不共享。

**原因**：默认使用内存存储限流状态，各实例独立计数。

**解决**：启用 Redis 共享限流状态：
```env
APP_REDIS_ENABLED=true
REDIS_HOST=redis
REDIS_PASSWORD=<密码>
```

## 十一、安全加固建议

### 已内置的安全机制

- 接口限流（`RateLimitService`）：防止暴力破解和恶意请求
- 登录验证码（`LoginCaptchaService`）：连续登录失败后强制验证码验证
- HTTP 安全头（`SecurityHeadersFilter`）：CSP、X-Frame-Options 等自动注入
- SSRF 防护（`OutboundUrlGuard`）：网页导入功能阻止访问内网地址
- Token 版本失效（`tokenVersion`）：修改密码/登出后旧 Token 立即失效
- BCrypt 密码加密：12 轮 BCrypt，旧版 SHA-256 密码自动升级
- Token 有效期默认 1 天（原 7 天）
- 限流状态支持内存/Redis 双后端（`ShortTermStateStore` 策略模式）

### 必须做的

- `.env` 文件权限设为 600（只有 root 可读写）：`chmod 600 /opt/learning-assistant/.env`
- `APP_AUTH_SECRET` 使用长随机字符串（至少 32 位）
- `APP_ADMIN_PASSWORD` 使用强密码（至少 12 位）
- MySQL root 密码使用强密码
- 不要开放 3306 和 8080 端口到公网
- SMTP 密码使用授权码，不是邮箱登录密码
- 确认 `.env` 不在 Git 仓库中

### 推荐做的

- 定期备份 `mysql-data/` 和 `app-data/` 目录
- 配置 HTTPS（使用 Let's Encrypt 免费证书 + Certbot）
- 定期更新 Docker 镜像：`docker compose pull`
- 设置服务器监控告警（阿里云控制台自带）
- 定期检查日志中是否有异常：`docker compose logs | grep ERROR`

### HTTPS 配置（可选）

```bash
# 安装 Certbot
apt install -y certbot

# 获取证书（需要域名解析到服务器 IP）
certbot certonly --standalone -d your-domain.com

# 修改 nginx.conf 添加 SSL 配置
# 添加 443 端口监听和证书路径
```
