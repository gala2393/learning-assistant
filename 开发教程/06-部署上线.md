# 课程学习助手 — 项目开发完全指南（六）：部署上线

> 本文档教你如何把项目部署到阿里云轻量应用服务器上，使用 Docker Compose 编排所有服务，让任何人都能通过公网访问。

---

## 一、部署架构总览

本项目使用**阿里云轻量应用服务器 + Docker Compose + Nginx**方案。

### 1.1 整体架构图

```
用户浏览器
   │
   ▼
阿里云轻量应用服务器 (公网 IP)
   │
   ├── Nginx (端口 80)
   │   ├── /          → 前端静态文件 (/opt/learning-assistant/frontend-dist)
   │   └── /api/*     → 反向代理到后端 (http://backend:8080)
   │
   └── Docker Compose (3 个容器在同一网络)
       ├── mysql      → MySQL 8 数据库 (数据卷: mysql-data)
       ├── backend    → Spring Boot 后端容器 (文件存: app-data)
       └── nginx      → 前端静态资源 + /api 反向代理
```

### 1.2 各组件职责

| 组件 | 作用 | 通俗解释 |
|------|------|---------|
| **阿里云轻量服务器** | 一台 24 小时在线的云电脑 | 项目的"家" |
| **Docker Compose** | 一键启动/停止/更新所有服务 | 项目的"遥控器" |
| **MySQL 容器** | 存储用户、资料、问答等数据 | 项目的"记忆" |
| **Backend 容器** | 运行 Spring Boot 后端程序 | 项目的"大脑" |
| **Nginx 容器** | 托管前端页面 + 转发 API 请求 | 项目的"门面" |
| **MobaXterm** | 本地向服务器上传文件的工具 | 项目的"快递员" |

### 1.3 为什么不用 Railway + Vercel 了？

最初版本部署在 Railway（后端）+ Vercel（前端）上。后来迁移到了阿里云，原因：
- 阿里云服务器在国内访问更快（低延迟）
- Docker Compose 可以一键管理所有服务，不依赖外部平台
- 数据完全在自己手里，不受第三方平台限制
- 月费固定，不按使用量计费

## 二、服务器初始配置

### 2.1 购买阿里云轻量应用服务器

1. 访问 [aliyun.com](https://www.aliyun.com)，搜索"轻量应用服务器"
2. 选择配置（推荐 2 核 2G 以上）
3. 地域选择靠近用户的区域（中国大陆选华东/华北）
4. 镜像选择 **Ubuntu 22.04**（或 24.04）
5. 购买后获取**公网 IP** 和 **root 密码**

### 2.2 连接到服务器

使用 SSH 工具连接服务器。项目提供了密钥文件 `aliyun-learning.ppk`（位于项目根目录）。

**方式一：使用 MobaXterm**（推荐给新手）：
1. 打开 MobaXterm，点击 Session → SSH
2. Remote host 填入公网 IP
3. 勾选 "Use private key"，选择 `aliyun-learning.ppk`
4. 连接成功后进入命令行

**方式二：使用命令行**：
```bash
ssh root@<你的公网IP>
# 输入密码登录
```

### 2.3 安装 Docker

连接到服务器后，逐行执行以下命令：

```bash
# 更新软件包列表
apt update

# 安装 Docker
apt install -y docker.io

# 安装 Docker Compose（独立版）
apt install -y docker-compose-v2

# 验证安装
docker --version
docker compose version

# 设置 Docker 开机自启
systemctl enable docker
systemctl start docker
```

### 2.4 创建项目目录结构

在服务器上创建以下目录：

```bash
mkdir -p /opt/learning-assistant/repo/backend
mkdir -p /opt/learning-assistant/repo/frontend
mkdir -p /opt/learning-assistant/frontend-dist
mkdir -p /opt/learning-assistant/mysql-data
mkdir -p /opt/learning-assistant/app-data
mkdir -p /opt/learning-assistant/nginx
```

目录说明：

| 目录 | 用途 |
|------|------|
| `/opt/learning-assistant/repo/backend` | 后端代码和 Dockerfile |
| `/opt/learning-assistant/repo/frontend` | 前端源代码 |
| `/opt/learning-assistant/frontend-dist` | 前端构建产物（npm run build 输出） |
| `/opt/learning-assistant/mysql-data` | MySQL 数据持久化（容器重启数据不丢失） |
| `/opt/learning-assistant/app-data` | 用户上传的文件（PDF、图片等） |
| `/opt/learning-assistant/nginx` | Nginx 配置文件 |

### 2.5 配置防火墙

在阿里云控制台开放端口：
1. 进入轻量应用服务器 → 防火墙
2. 添加规则：开放 **80 端口**（HTTP）
3. 如果需要 HTTPS，也开放 **443 端口**

> 不要开放 3306（MySQL）和 8080（后端）端口！这些只在 Docker 内网通信，对外暴露有安全风险。

### 3.3 什么是 Dockerfile？

Dockerfile 就像一份"做菜食谱"，告诉 Docker 如何构建一个容器镜像。

后端 Dockerfile 的关键内容：

```dockerfile
# 第一阶段：编译 Java 项目
FROM eclipse-temurin:21-jdk-jammy AS builder
WORKDIR /workspace
COPY . .
RUN ./mvnw -q -DskipTests clean package

# 第二阶段：运行时（只包含 JRE，更小）
FROM eclipse-temurin:21-jre-jammy
RUN apt-get update && apt-get install -y \
    ghostscript \              # PDF 压缩
    libreoffice \              # Office 文档转 PDF
    tesseract-ocr \            # OCR 文字识别
    tesseract-ocr-chi-sim \    # 中文 OCR 语言包
    fonts-noto-cjk \           # 中文字体
    && rm -rf /var/lib/apt/lists/*
COPY --from=builder /workspace/app.jar /app/app.jar
ENV SPRING_PROFILES_ACTIVE=prod
ENV APP_STORAGE_DIR=/data/learning-assistant-files
EXPOSE 8080
```

> **两阶段构建的好处**：编译工具（JDK、Maven）加起来几百 MB，但运行时不需要。最终镜像只包含 JRE + 系统工具，体积小很多。

## 五、创建 Docker Compose 配置

### 5.1 docker-compose.yml

在服务器上创建 `/opt/learning-assistant/docker-compose.yml`：

```bash
cat > /opt/learning-assistant/docker-compose.yml << 'DOCKEREOF'
version: "3.8"

services:
  mysql:
    image: mysql:8.0
    container_name: la-mysql
    restart: unless-stopped
    environment:
      MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD}
      MYSQL_DATABASE: learning_assistant
      MYSQL_CHARSET: utf8mb4
      MYSQL_COLLATION: utf8mb4_unicode_ci
    volumes:
      - ./mysql-data:/var/lib/mysql
    ports:
      - "127.0.0.1:3306:3306"   # 只监听本地，不对外暴露
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost"]
      interval: 10s
      timeout: 5s
      retries: 5

  backend:
    build:
      context: ./repo/backend
      dockerfile: Dockerfile
    container_name: la-backend
    restart: unless-stopped
    environment:
      - SPRING_PROFILES_ACTIVE=prod
      - SERVER_PORT=8080
      - MYSQL_URL=jdbc:mysql://mysql:3306/learning_assistant?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true
      - MYSQL_USERNAME=root
      - MYSQL_PASSWORD=${MYSQL_ROOT_PASSWORD}
      - JPA_DDL_AUTO=${JPA_DDL_AUTO:-validate}
      - FLYWAY_ENABLED=${FLYWAY_ENABLED:-true}
      - FLYWAY_BASELINE_ON_MIGRATE=true
      - APP_AUTH_SECRET=${APP_AUTH_SECRET}
      - APP_STORAGE_DIR=/data/learning-assistant-files
      - APP_CORS_ALLOWED_ORIGINS=${APP_CORS_ALLOWED_ORIGINS:-http://localhost}
      - LLM_ENABLED=${LLM_ENABLED:-false}
      - LLM_BASE_URL=${LLM_BASE_URL:-}
      - LLM_API_KEY=${LLM_API_KEY:-}
      - LLM_MODEL=${LLM_MODEL:-}
      - LLM_API_FORMAT=${LLM_API_FORMAT:-chat-completions}
      - LLM_TIMEOUT=${LLM_TIMEOUT:-60s}
      - EMBEDDING_ENABLED=${EMBEDDING_ENABLED:-false}
      - EMBEDDING_BASE_URL=${EMBEDDING_BASE_URL:-}
      - EMBEDDING_API_KEY=${EMBEDDING_API_KEY:-}
      - EMBEDDING_MODEL=${EMBEDDING_MODEL:-text-embedding-v3}
      - EMBEDDING_TIMEOUT=${EMBEDDING_TIMEOUT:-30s}
      - EMBEDDING_TOP_K=${EMBEDDING_TOP_K:-5}
      - EMBEDDING_SCORE_THRESHOLD=${EMBEDDING_SCORE_THRESHOLD:-0.55}
      - EMAIL_CODE_ENABLED=${EMAIL_CODE_ENABLED:-false}
      - EMAIL_CODE_DEFAULT_PROVIDER=${EMAIL_CODE_DEFAULT_PROVIDER:-qq}
      - SMTP_HOST=${SMTP_HOST:-}
      - SMTP_PORT=${SMTP_PORT:-465}
      - SMTP_USERNAME=${SMTP_USERNAME:-}
      - SMTP_PASSWORD=${SMTP_PASSWORD:-}
      - EMAIL_CODE_QQ_HOST=${EMAIL_CODE_QQ_HOST:-smtp.qq.com}
      - EMAIL_CODE_QQ_PORT=${EMAIL_CODE_QQ_PORT:-465}
      - EMAIL_CODE_QQ_USERNAME=${EMAIL_CODE_QQ_USERNAME:-}
      - EMAIL_CODE_QQ_PASSWORD=${EMAIL_CODE_QQ_PASSWORD:-}
      - EMAIL_CODE_QQ_FROM=${EMAIL_CODE_QQ_FROM:-}
      - EMAIL_CODE_NETEASE_HOST=${EMAIL_CODE_NETEASE_HOST:-smtp.163.com}
      - EMAIL_CODE_NETEASE_PORT=${EMAIL_CODE_NETEASE_PORT:-465}
      - EMAIL_CODE_NETEASE_USERNAME=${EMAIL_CODE_NETEASE_USERNAME:-}
      - EMAIL_CODE_NETEASE_PASSWORD=${EMAIL_CODE_NETEASE_PASSWORD:-}
      - EMAIL_CODE_NETEASE_FROM=${EMAIL_CODE_NETEASE_FROM:-}
      - OCR_ENABLED=${OCR_ENABLED:-false}
      - OCR_LANG=${OCR_LANG:-eng+chi_sim}
      - DOCUMENT_PREVIEW_CONVERTER_ENABLED=${DOCUMENT_PREVIEW_CONVERTER_ENABLED:-true}
      - PDF_COMPRESSION_ENABLED=${PDF_COMPRESSION_ENABLED:-true}
      - QUERY_EXPANSION_ENABLED=${QUERY_EXPANSION_ENABLED:-true}
      - RERANKER_ENABLED=${RERANKER_ENABLED:-true}
      - VECTOR_STORE_ENABLED=${VECTOR_STORE_ENABLED:-false}
    volumes:
      - ./app-data:/data/learning-assistant-files
    depends_on:
      mysql:
        condition: service_healthy
    ports:
      - "127.0.0.1:8080:8080"   # 只监听本地，由 Nginx 转发

  nginx:
    image: nginx:stable-alpine
    container_name: la-nginx
    restart: unless-stopped
    volumes:
      - ./frontend-dist:/usr/share/nginx/html:ro
      - ./nginx/nginx.conf:/etc/nginx/conf.d/default.conf:ro
    ports:
      - "80:80"
    depends_on:
      - backend

DOCKEREOF
```

> **关键配置说明**：
> - `MYSQL_URL` 中使用 `mysql:3306`（容器服务名），不是 `127.0.0.1`
> - `127.0.0.1:3306:3306` 和 `127.0.0.1:8080:8080` 保证数据库和后端不对外暴露
> - `depends_on` + `healthcheck` 确保 MySQL 启动完成后才启动后端
> - `volumes` 挂载实现数据持久化

### 5.2 Nginx 配置

在服务器上创建 `/opt/learning-assistant/nginx/nginx.conf`：

```bash
cat > /opt/learning-assistant/nginx/nginx.conf << 'NGINXEOF'
server {
    listen 80;
    server_name _;

    # 上传文件大小限制
    client_max_body_size 500m;

    # 前端静态文件
    location / {
        root /usr/share/nginx/html;
        index index.html;
        # SPA 路由支持：找不到文件时返回 index.html
        try_files $uri $uri/ /index.html;
    }

    # API 反向代理到后端
    location /api/ {
        proxy_pass http://backend:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # SSE 流式输出支持（AI 打字机效果）
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 120s;
        proxy_send_timeout 120s;
    }
}
NGINXEOF
```

> **重要配置**：
> - `try_files $uri $uri/ /index.html` — 解决刷新页面 404 问题（SPA 路由）
> - `proxy_buffering off` — 关闭缓冲，否则 AI 回答会等全部生成完才显示
> - `proxy_read_timeout 120s` — 120 秒超时，避免长回答被截断
> - `client_max_body_size 500m` — 允许上传大文件

### 5.3 环境变量文件 (.env)

在服务器上创建 `/opt/learning-assistant/.env`：

```bash
cat > /opt/learning-assistant/.env << 'ENVEOF'
# ===== 数据库 =====
MYSQL_ROOT_PASSWORD=<设置一个强密码>
JPA_DDL_AUTO=validate
FLYWAY_ENABLED=true

# ===== 认证密钥 =====
APP_AUTH_SECRET=<生成一个随机字符串，至少32位>

# ===== CORS =====
APP_CORS_ALLOWED_ORIGINS=http://<你的公网IP>,http://localhost

# ===== LLM 大模型 =====
LLM_ENABLED=true
LLM_BASE_URL=<你的LLM接口地址>
LLM_API_KEY=<你的API Key>
LLM_MODEL=<模型名>
LLM_API_FORMAT=responses

# ===== 邮箱验证（可选） =====
EMAIL_CODE_ENABLED=true
EMAIL_CODE_DEFAULT_PROVIDER=qq
EMAIL_CODE_QQ_HOST=smtp.qq.com
EMAIL_CODE_QQ_PORT=465
EMAIL_CODE_QQ_USERNAME=<你的QQ邮箱>
EMAIL_CODE_QQ_PASSWORD=<QQ邮箱的SMTP授权码>
EMAIL_CODE_QQ_FROM=<你的QQ邮箱>

# ===== OCR =====
OCR_ENABLED=true
OCR_LANG=eng+chi_sim

# ===== 文档预览 =====
DOCUMENT_PREVIEW_CONVERTER_ENABLED=true

# ===== 查询增强 =====
QUERY_EXPANSION_ENABLED=true
RERANKER_ENABLED=true
ENVEOF
```

**如何生成 `APP_AUTH_SECRET`？**

```bash
# 在服务器上执行
openssl rand -hex 32
```

**QQ 邮箱授权码获取步骤**：
1. 登录 QQ 邮箱网页版
2. 设置 → 账户 → POP3/IMAP/SMTP 服务
3. 开启 SMTP 服务，按提示发送短信
4. 获取到的 16 位授权码就是 `EMAIL_CODE_QQ_PASSWORD`

## 六、首次部署

### 6.1 启动所有服务

```bash
cd /opt/learning-assistant

# 启动（首次会自动构建后端镜像，约需 5-10 分钟）
docker compose up -d --build
```

首次启动流程：
1. Docker 拉取 MySQL 8 和 Nginx 镜像
2. 构建后端镜像（下载 JDK、Maven 依赖、安装系统工具）
3. 启动 MySQL 容器
4. 等待 MySQL 健康检查通过
5. 启动后端容器（Flyway 自动建表，创建默认 admin 用户）
6. 启动 Nginx 容器

### 6.2 查看运行状态

```bash
# 查看所有容器状态
docker compose ps

# 应该看到 3 个容器都是 Up 状态
# la-mysql    Up (healthy)
# la-backend  Up
# la-nginx    Up
```

### 6.3 查看日志

```bash
# 查看后端日志（按 Ctrl+C 退出）
docker compose logs -f backend

# 查看所有服务日志
docker compose logs -f

# 查看最近 50 行
docker compose logs --tail=50 backend
```

### 6.4 验证部署成功

```bash
# 在服务器上测试
curl http://127.0.0.1/api/health

# 应该返回：{"status":"ok","service":"learning-assistant"}
```

在浏览器中访问 `http://<你的公网IP>`，应该看到登录页面。

## 十、常见问题排查

### Q1：容器启动失败

**症状**：`docker compose up` 后容器反复重启。

**排查步骤**：
```bash
# 查看具体错误
docker compose logs backend
# 常见原因：环境变量未设置、MySQL 连接失败、端口占用
```

### Q2：MySQL 连接失败

**症状**：后端日志显示 `Communications link failure`。

**原因**：`MYSQL_URL` 写错了。

**解决**：Docker Compose 环境中，数据库地址必须是**容器服务名** `mysql`，不能写 `127.0.0.1`：
```env
MYSQL_URL=jdbc:mysql://mysql:3306/learning_assistant?useUnicode=true&...
```

### Q3：刷新页面显示 404

**症状**：登录后刷新 `/workspace/chat` 等页面出现 404。

**原因**：Nginx 没有配置 SPA 路由重写。

**解决**：确认 `nginx.conf` 中有：
```nginx
location / {
    try_files $uri $uri/ /index.html;
}
```

### Q4：文件上传后丢失

**症状**：上传的资料文件在容器重启后消失。

**原因**：没有挂载持久化数据卷，文件存在容器内部。

**解决**：确认 `docker-compose.yml` 中配置了 volumes：
```yaml
volumes:
  - ./app-data:/data/learning-assistant-files
```

### Q5：AI 回答不流式输出

**症状**：AI 回答不是逐字出现，而是等全部完成后一次性显示。

**原因**：Nginx 开启了响应缓冲。

**解决**：在 Nginx 配置的 `/api/` location 中添加：
```nginx
proxy_buffering off;
proxy_cache off;
```

### Q6：CORS 跨域错误

**症状**：浏览器控制台显示 `Access-Control-Allow-Origin` 错误。

**解决**：
1. 确认 `.env` 中 `APP_CORS_ALLOWED_ORIGINS` 包含当前访问的域名
2. 注意协议（http vs https）和端口
3. 修改后需要重启后端：`docker compose restart backend`

### Q7：邮箱验证码收不到

**排查**：
1. 检查垃圾邮件文件夹
2. 确认 SMTP 授权码正确（不是邮箱登录密码）
3. QQ 邮箱：设置 → 账户 → POP3/IMAP/SMTP → 生成授权码
4. 确认 `EMAIL_CODE_ENABLED=true`

### Q8：Docker 构建太慢

**原因**：首次构建需要下载 Java、Maven 依赖、LibreOffice 等。

**解决**：
- 首次构建 5-10 分钟是正常的
- 后续构建会使用 Docker 缓存，通常 1-3 分钟
- 如果只改 Java 代码不改 Dockerfile，构建很快

### Q9：端口被占用

**症状**：`bind: address already in use`。

**解决**：
```bash
# 查看占用 80 端口的进程
lsof -i :80

# 如果之前有其他 Nginx/Apache 在运行，先停止
systemctl stop nginx
systemctl stop apache2
```

### Q10：LLM 对话不工作

**症状**：发送消息后无响应或报错。

**排查**：
1. 确认 `LLM_ENABLED=true`
2. 检查 `LLM_BASE_URL` 和 `LLM_API_KEY`
3. 确认 `LLM_API_FORMAT` 与 API 提供商兼容
4. API 额度是否充足

## 十一、安全加固建议

### 必须做的

- `.env` 文件权限设为 600（只有 root 可读写）：`chmod 600 /opt/learning-assistant/.env`
- `APP_AUTH_SECRET` 使用长随机字符串（至少 32 位）
- MySQL root 密码使用强密码
- 不要开放 3306 和 8080 端口到公网
- SMTP 密码使用授权码，不是邮箱登录密码
- 确认 `.env` 不在 Git 仓库中

### 推荐做的

- 定期备份 `mysql-data/` 和 `app-data/` 目录
- 配置 HTTPS（使用 Let's Encrypt 免费证书 + Certbot）
- 定期更新 Docker 镜像：`docker compose pull`
- 设置服务器监控告警（阿里云控制台自带）
- 定期检查日志中是否有异常：`docker compose logs | grep ERROR`

### HTTPS 配置（可选）

```bash
# 安装 Certbot
apt install -y certbot

# 获取证书（需要域名解析到服务器 IP）
certbot certonly --standalone -d your-domain.com

# 修改 nginx.conf 添加 SSL 配置
# 添加 443 端口监听和证书路径
```
