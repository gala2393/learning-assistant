# 课程学习助手 — 项目开发完全指南（六）：部署上线

> 本文档教你如何把这个项目部署到互联网上，让任何人都能访问。内容包括：线上架构总览、数据库准备、后端部署、前端部署、本地开发环境搭建，以及常见问题排查。

---

## 一、部署架构

先把全局架构看清楚。本项目采用**前后端分离**部署方案：

```
用户浏览器
   │
   ├──► Vercel（前端静态站点）
   │       https://your-app.vercel.app
   │       提供 React 打包后的 HTML/CSS/JS
   │
   └──► Railway（后端 Spring Boot）
           https://your-backend.railway.app/api
           ┌─────────────────────────────────┐
           │  Docker 容器                     │
           │  ┌───────────┐  ┌─────────────┐ │
           │  │ Spring Boot│  │ LibreOffice │ │
           │  │ Java 21    │  │ Tesseract   │ │
           │  │            │  │ Ghostscript │ │
           │  └─────┬──────┘  └─────────────┘ │
           └────────┼─────────────────────────┘
                    │
           ┌────────┴────────┐
           │                 │
     ┌─────┴─────┐   ┌──────┴──────┐
     │ Railway    │   │ Railway     │
     │ MySQL 数据库│   │ Volume 磁盘 │
     │            │   │ /data       │
     └────────────┘   └─────────────┘
```

**简单解释：**
- **Vercel** 负责托管前端页面（纯静态文件，加载速度快）
- **Railway** 负责运行后端服务（Java 程序 + 文档处理工具）
- **Railway MySQL** 是数据库，存储用户账号、资料记录等
- **Railway Volume** 是一块持久化磁盘，存用户上传的文件（PDF、图片等）

> 前端通过 HTTPS 请求后端 API，后端读写数据库和文件存储。用户只看到 Vercel 的地址，不直接接触 Railway。

## 二、准备数据库

在 Railway 上创建 MySQL 数据库是第一步，因为后端启动时需要连接它。

### 2.1 创建 Railway 项目

1. 打开浏览器，访问 [railway.com](https://railway.com)
2. 点击右上角 **"Login"**，用 GitHub 账号登录
3. 登录后，在 Dashboard 页面点击 **"New Project"**
4. 在弹出菜单中选择 **"Provision MySQL"**

> 页面会自动创建一个 MySQL 数据库服务。创建完成后，点击该服务卡片，进入详情页。

### 2.2 获取数据库连接信息

在 MySQL 服务详情页，切换到 **"Variables"** 标签页，你会看到以下变量（Railway 自动生成）：

| 变量名 | 含义 | 示例值 |
|--------|------|--------|
| `MYSQLHOST` | 数据库地址 | `containers-us-west-xxx.railway.app` |
| `MYSQLPORT` | 端口 | `6543` |
| `MYSQLDATABASE` | 数据库名 | `railway` |
| `MYSQLUSER` | 用户名 | `root` |
| `MYSQLPASSWORD` | 密码 | `xxxxxxxxxxxx` |

把这些值记下来，后面配置后端时要用到。

### 2.3 拼接 JDBC 连接串

后端需要一个完整的 JDBC URL，格式如下：

```
jdbc:mysql://<MYSQLHOST>:<MYSQLPORT>/<MYSQLDATABASE>?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true
```

举例，如果你的 `MYSQLHOST` 是 `containers-us-west-1.railway.app`，端口是 `6543`，数据库名是 `railway`，那么完整连接串是：

```
jdbc:mysql://containers-us-west-1.railway.app:6543/railway?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true
```

> 数据库不需要手动建表。后端启动时会根据 `JPA_DDL_AUTO=update` 自动创建所有表结构。

## 三、部署后端

### 3.1 Docker 打包原理

后端使用 **多阶段 Dockerfile**（Multi-stage Build）打包。这个 Dockerfile 做了两件事：

**第一阶段（Builder）**：在容器里编译 Java 项目

```dockerfile
FROM eclipse-temurin:21-jdk-jammy AS builder
WORKDIR /workspace
COPY . .
RUN ./mvnw -q -DskipTests clean package
```

- `eclipse-temurin:21-jdk-jammy` 是包含 Java 21 编译器的镜像
- `./mvnw` 是 Maven Wrapper，自动下载 Maven 并编译项目
- `-DskipTests` 跳过测试，加快构建速度
- 最终产出一个 `.jar` 文件

**第二阶段（Runtime）**：只包含运行时需要的东西

```dockerfile
FROM eclipse-temurin:21-jre-jammy
RUN apt-get update && apt-get install -y \
    ghostscript \        # PDF 压缩
    libreoffice \        # Office 文档转 PDF
    tesseract-ocr \      # OCR 文字识别
    tesseract-ocr-chi-sim \  # 中文 OCR
    fonts-noto-cjk \     # 中文字体
    && rm -rf /var/lib/apt/lists/*
COPY --from=builder /workspace/app.jar /app/app.jar
```

- `eclipse-temurin:21-jre-jammy` 只有运行时（JRE），比 JDK 镜像小很多
- 安装了文档处理所需的系统工具
- `COPY --from=builder` 从第一阶段拷贝编译好的 jar 包

**关键环境变量：**

```dockerfile
ENV SPRING_PROFILES_ACTIVE=prod    # 使用生产环境配置
ENV APP_STORAGE_DIR=/data/learning-assistant-files  # 文件存储路径
EXPOSE 8080                        # 监听 8080 端口
```

> **为什么用两阶段构建？** 因为编译工具（JDK、Maven）加起来有几百 MB，但运行时根本不需要它们。两阶段构建让最终镜像小很多，部署更快。

### 3.2 Railway 部署步骤

#### 步骤 1：创建后端服务

1. 进入你刚才创建的 Railway 项目（包含 MySQL 的那个）
2. 点击项目页面右上角的 **"+"** 按钮
3. 选择 **"GitHub Repo"**
4. 如果是第一次，Railway 会要求你授权访问 GitHub 仓库，点击授权
5. 选择你的 `learning-assistant` 仓库
6. **不要点 "Deploy Now"**，先进行下面的配置

#### 步骤 2：配置根目录和构建方式

1. 点击刚创建的后端服务卡片
2. 切换到 **"Settings"** 标签页
3. 在 **"Source"** 区域，设置 **Root Directory** 为 `backend`
4. Railway 会自动检测到 `backend/railway.json`，使用其中的 Dockerfile 配置

> `backend/railway.json` 告诉 Railway 用 `backend/Dockerfile` 构建，并在部署后检查 `/api/health` 健康接口。

#### 步骤 3：添加持久化磁盘（Volume）

1. 在后端服务的 **Settings** 页面，找到 **"Volumes"** 区域
2. 点击 **"Add Volume"**
3. **Mount Path** 填 `/data`
4. 点击确认

> 这样用户上传的文件就会保存在这个持久化磁盘上，即使服务重启也不会丢失。

#### 步骤 4：生成公开域名

1. 在后端服务的 **Settings** 页面，找到 **"Networking"** 区域
2. 点击 **"Generate Domain"**
3. Railway 会分配一个类似 `your-backend-production.up.railway.app` 的域名
4. 记下这个域名，后面要用

#### 步骤 5：配置环境变量

1. 切换到 **"Variables"** 标签页
2. 点击 **"Raw Editor"**，可以批量粘贴变量
3. 把下面的变量逐项填入（把 `<>` 中的占位符替换成真实值）：

```env
# ===== 基础配置 =====
SPRING_PROFILES_ACTIVE=prod
JPA_DDL_AUTO=update

# ===== 数据库 =====
MYSQL_URL=jdbc:mysql://<MYSQLHOST>:<MYSQLPORT>/<MYSQLDATABASE>?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true
MYSQL_USERNAME=<MYSQLUSER>
MYSQL_PASSWORD=<MYSQLPASSWORD>

# ===== 认证 =====
APP_AUTH_SECRET=<生成一个随机字符串，见下方说明>

# ===== 文件存储 =====
APP_STORAGE_DIR=/data/learning-assistant-files

# ===== CORS 跨域 =====
APP_CORS_ALLOWED_ORIGINS=https://<你的Vercel域名>.vercel.app

# ===== 邮箱验证登录（可选） =====
EMAIL_CODE_ENABLED=true
EMAIL_CODE_DEFAULT_PROVIDER=qq
EMAIL_CODE_QQ_HOST=smtp.qq.com
EMAIL_CODE_QQ_PORT=465
EMAIL_CODE_QQ_USERNAME=<你的QQ邮箱>
EMAIL_CODE_QQ_PASSWORD=<QQ邮箱的SMTP授权码>
EMAIL_CODE_QQ_FROM=<你的QQ邮箱>

# ===== LLM 大语言模型 =====
LLM_ENABLED=true
LLM_BASE_URL=<你的LLM接口地址，如 https://api.openai.com>
LLM_API_KEY=<你的API Key>
LLM_MODEL=<模型名，如 gpt-4o>
LLM_TIMEOUT=30s

# ===== Embedding 向量化（可选，用于 RAG） =====
EMBEDDING_ENABLED=true
EMBEDDING_BASE_URL=<你的Embedding接口地址>
EMBEDDING_API_KEY=<你的Embedding API Key>
EMBEDDING_MODEL=text-embedding-v3
EMBEDDING_TIMEOUT=30s
EMBEDDING_TOP_K=5

# ===== OCR 和文档预览 =====
OCR_ENABLED=true
OCR_LANG=eng+chi_sim
DOCUMENT_PREVIEW_CONVERTER_ENABLED=true
```

**如何生成 `APP_AUTH_SECRET`？**

在终端运行以下命令生成一个随机字符串：

```bash
openssl rand -hex 32
```

或者用 PowerShell：

```powershell
-join ((1..64) | ForEach-Object { '{0:X}' -f (Get-Random -Maximum 16) })
```

> **重要：** `APP_AUTH_SECRET` 是签发登录令牌的密钥。如果这个值变了，所有已登录用户会被强制登出。请保存好这个值，不要随意更改。

#### 步骤 6：部署

1. 配置好所有环境变量后，Railway 会自动触发一次部署
2. 切换到 **"Deployments"** 标签页，查看构建日志
3. 等待构建完成（首次构建约需 5-10 分钟，因为要下载依赖和安装 LibreOffice）
4. 构建完成后，Railway 会执行健康检查（`/api/health`）
5. 看到绿色的 **"Active"** 状态表示部署成功

**验证方法：** 在浏览器打开 `https://<你的后端域名>/api/health`，应该看到一个 JSON 响应。

### 3.3 环境变量速查表

| 变量名 | 是否必须 | 说明 | 示例值 |
|--------|---------|------|--------|
| `SPRING_PROFILES_ACTIVE` | 必须 | Spring 配置文件 | `prod` |

## 四、部署前端

### 4.1 Vercel 部署步骤

#### 步骤 1：注册并导入项目

1. 打开 [vercel.com](https://vercel.com)
2. 点击 **"Sign Up"**，选择用 GitHub 账号注册/登录
3. 登录后，进入 Dashboard，点击 **"Add New..."** -> **"Project"**
4. 在列表中找到你的 `learning-assistant` 仓库，点击 **"Import"**

#### 步骤 2：配置构建参数

在项目配置页面：

| 配置项 | 填写值 |
|--------|--------|
| **Framework Preset** | `Vite`（通常自动检测） |
| **Root Directory** | 点击 "Edit"，输入 `frontend` |
| **Build Command** | `npm run build` |
| **Output Directory** | `dist` |

> 如果你在项目根目录有 `vercel.json`，Vercel 会自动使用其中的配置。`vercel.json` 已经设好了 `installCommand`、`buildCommand` 和 `outputDirectory`。

#### 步骤 3：配置环境变量

展开 **"Environment Variables"** 区域，添加：

| 变量名 | 值 |
|--------|----|
| `VITE_API_BASE` | `https://<你的Railway后端域名>/api` |

举例：
```
VITE_API_BASE=https://your-backend-production.up.railway.app/api
```

> **注意：** `VITE_API_BASE` 是在**构建时**嵌入到前端代码中的（Vite 的特性），所以必须在部署前设置好，不能在运行时更改。

#### 步骤 4：部署

1. 点击 **"Deploy"**
2. 等待构建完成（约 1-2 分钟）
3. 构建成功后，Vercel 会显示预览页面和一个 `.vercel.app` 域名
4. 点击域名，可以看到你的应用

### 4.2 路由重写（SPA 配置）

前端是单页应用（SPA），所有路由由 React Router 在浏览器端处理。为了让刷新页面时不出现 404，需要配置路由重写。

项目根目录的 `vercel.json` 已经配置好了：

```json
{
  "rewrites": [
    {
      "source": "/((?!api/).*)",
      "destination": "/index.html"
    }
  ]
}
```

这行配置的意思是：**任何不以 `/api/` 开头的请求**，都返回 `index.html`，让 React Router 接管路由。

> 你不需要手动配置，Vercel 会自动读取 `vercel.json`。

### 4.3 更新后端 CORS

前端部署完成后，你需要把 Vercel 的域名告诉后端，否则浏览器会拦截 API 请求（CORS 错误）。

1. 回到 Railway 后端服务的 **Variables** 页面
2. 修改 `APP_CORS_ALLOWED_ORIGINS`，添加 Vercel 域名：

```
APP_CORS_ALLOWED_ORIGINS=https://你的前端域名.vercel.app
```

如果需要支持多个域名（例如 Vercel 的预览部署），用逗号分隔：

```
APP_CORS_ALLOWED_ORIGINS=https://my-app.vercel.app,https://*.vercel.app
```

> 保存后 Railway 会自动重新部署后端。等待新的部署完成后，刷新前端页面即可正常使用。

## 五、本地开发环境搭建

如果你想在自己的电脑上开发和调试，需要搭建本地环境。

### 5.1 安装依赖

**必需：**
- **Java 21**（JDK）：[下载 Eclipse Temurin](https://adoptium.net/temurin/releases/?version=21)
- **Node.js 18+**：[下载 Node.js](https://nodejs.org/)
- **MySQL 8**：[下载 MySQL Community](https://dev.mysql.com/downloads/mysql/)

**可选（对应功能）：**
- **Tesseract OCR**：用于图片文字识别
- **LibreOffice**：用于 Office 文档预览
- **Ghostscript**：用于 PDF 压缩

### 5.2 配置 MySQL

1. 安装并启动 MySQL 服务
2. 用命令行或 Navicat 等工具连接 MySQL
3. 创建数据库：

```sql
CREATE DATABASE learning_assistant CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

> 不需要手动建表。后端启动时会自动创建。

### 5.3 配置并启动后端

1. 进入 `backend` 目录，复制环境变量文件：

```bash
cd backend
cp .env.example .env.local
```

2. 编辑 `.env.local`，至少修改以下几项：

```env
# 数据库 — 改成你本地 MySQL 的信息
MYSQL_URL=jdbc:mysql://127.0.0.1:3306/learning_assistant?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true
MYSQL_USERNAME=root
MYSQL_PASSWORD=你本地MySQL的密码

# 文件存储 — 本地开发用相对路径即可
APP_STORAGE_DIR=./data/learning-assistant-files

# 认证密钥
APP_AUTH_SECRET=本地开发随便填一个字符串就行

# CORS — 允许本地前端
APP_CORS_ALLOWED_ORIGINS=http://localhost:5174
```

3. 启动后端（Windows）：

```cmd
cd backend
start-backend.cmd
```

或用 PowerShell：

```powershell
cd backend
.\start-backend.ps1
```

或手动启动：

```bash
cd backend
./mvnw spring-boot:run
```

> 后端启动后，访问 `http://localhost:8080/api/health` 验证。

### 5.4 配置并启动前端

1. 进入 `frontend` 目录，安装依赖：

```bash
cd frontend
npm install
```

2. 在 `frontend` 目录下创建 `.env` 文件：

```env
VITE_API_BASE=http://localhost:8080/api
```

3. 启动前端开发服务器：

```bash
npm run dev
```

> 前端启动后，访问 `http://localhost:5174` 即可。

### 5.5 可选：启动 Qdrant 向量数据库

如果要使用 RAG 问答功能的向量检索，需要启动 Qdrant：

```bash
cd backend
docker compose -f docker-compose.qdrant.yml up -d
```

然后在 `.env.local` 中启用：

```env
VECTOR_STORE_ENABLED=true
VECTOR_STORE_BASE_URL=http://127.0.0.1:6333
```

> Qdrant 默认不需要密码。数据存储在 Docker Volume 中，即使容器重启数据也不会丢失。

### 5.6 可选：安装 OCR 和文档处理工具

如果需要 OCR 识别和文档预览功能：

**Windows：**
- Tesseract：[下载安装包](https://github.com/UB-Mannheim/tesseract/wiki)，安装后将路径加入 PATH
- LibreOffice：[下载](https://www.libreoffice.org/download/download/)，安装即可
- Ghostscript：[下载](https://www.ghostscript.com/download/gsdnld.html)

**macOS：**
```bash
brew install tesseract tesseract-lang libreoffice ghostscript
```

**Ubuntu/Debian：**
```bash
sudo apt install tesseract-ocr tesseract-ocr-chi-sim libreoffice ghostscript fonts-noto-cjk
```

安装后在 `.env.local` 中启用：

```env
OCR_ENABLED=true
OCR_LANG=eng+chi_sim
DOCUMENT_PREVIEW_CONVERTER_ENABLED=true
```

## 六、常见问题排查

### Q1：前端页面打开后，API 请求全部报 CORS 错误

**症状：** 浏览器控制台显示 `Access to XMLHttpRequest has been blocked by CORS policy`。

**原因：** 后端没有允许前端的域名。

**解决：**
1. 登录 Railway，进入后端服务的 Variables 页面
2. 检查 `APP_CORS_ALLOWED_ORIGINS` 是否包含了你当前访问的前端域名
3. 注意不要有尾部斜杠（`/`），不要写错协议（`http` vs `https`）
4. 修改后等 Railway 自动重新部署

### Q2：登录后接口返回 401

**症状：** 登录成功，但刷新页面后所有请求返回 401 Unauthorized。

**原因：** `APP_AUTH_SECRET` 在部署后发生了变化，导致旧的令牌失效。

**解决：**
1. 确保 `APP_AUTH_SECRET` 设置后不要再更改
2. 如果是刚部署，清空浏览器 Cookie，重新登录即可
3. 确认前端 `VITE_API_BASE` 指向的是正确的后端地址

### Q3：文件上传失败

**症状：** 上传文件时报错，或上传后文件丢失（重启后丢失）。

**原因：** Railway Volume 没有正确挂载。

**解决：**
1. 进入 Railway 后端服务的 Settings 页面
2. 确认 Volume 的 Mount Path 是 `/data`
3. 确认环境变量 `APP_STORAGE_DIR` 是 `/data/learning-assistant-files`
4. 如果没有 Volume，点击 "Add Volume" 添加一个

### Q4：MySQL 连接失败

**症状：** 后端启动日志中显示 `Communications link failure` 或 `Access denied`。

**原因：** 数据库连接串或凭据不对。

**排查步骤：**
1. 检查 `MYSQL_URL` 的格式是否正确，特别注意端口号
2. 检查 `MYSQL_USERNAME` 和 `MYSQL_PASSWORD` 是否正确
3. 如果使用 Railway MySQL，确认 MySQL 服务和后端服务在同一个 Railway 项目中
4. 检查 MySQL 服务是否正在运行（在 Railway Dashboard 中查看）

### Q5：PDF 预览不工作

**症状：** 上传 PDF 后，预览区域空白或报错。

**原因：** Docker 容器中没有安装 LibreOffice/Ghostscript。

**解决：**
- 确认使用的是项目的 `Dockerfile` 部署（已经安装了 LibreOffice 和 Ghostscript）
- 如果本地开发，需要手动安装这些工具（见 5.6 节）
- 检查环境变量 `DOCUMENT_PREVIEW_CONVERTER_ENABLED=true`

### Q6：OCR 识别不工作

**症状：** 图片中的文字没有被提取出来。

**原因：** Tesseract 没有安装或语言包缺失。

**解决：**
- 确认 Docker 部署（Dockerfile 已安装 Tesseract 和中英文语言包）
- 本地开发时，手动安装 Tesseract（见 5.6 节）
- 检查 `OCR_ENABLED=true` 和 `OCR_LANG=eng+chi_sim`

### Q7：Vercel 部署后页面刷新 404

**症状：** 首页能打开，但刷新非首页路由（如 `/login`）出现 404。

**原因：** 路由重写配置缺失。

**解决：**
- 确认项目根目录有 `vercel.json`，包含 rewrite 规则
- 如果 Root Directory 设置为 `frontend`，则 `vercel.json` 应该在 `frontend` 目录下，或在项目根目录且已配置好 `rewrites`

### Q8：Railway 构建时间太长

**症状：** 每次部署要等 10 分钟以上。

**原因：** 首次构建需要下载大量依赖（Java、Maven 包、LibreOffice 等）。

**解决：**
- 首次构建慢是正常的，后续构建有 Docker 缓存会快很多
- 如果改动只涉及后端代码（不改 Dockerfile），构建时间通常在 2-3 分钟

### Q9：邮箱验证码收不到

**症状：** 注册或登录时点击"发送验证码"，但邮箱没收到。

**排查：**
1. 检查垃圾邮件文件夹
2. 确认 SMTP 相关环境变量是否正确（特别注意密码是**授权码**，不是邮箱登录密码）
3. QQ 邮箱的授权码在：QQ邮箱 -> 设置 -> 账户 -> POP3/IMAP/SMTP服务 -> 生成授权码
4. 检查 `EMAIL_CODE_ENABLED=true`
5. 查看 Railway 后端日志，搜索 SMTP 相关错误信息

### Q10：LLM 对话功能不工作

**症状：** 发送消息后长时间无响应，或返回错误。

**排查：**
1. 检查 `LLM_ENABLED=true`
2. 确认 `LLM_BASE_URL` 和 `LLM_API_KEY` 正确
3. 检查 API 额度是否充足
4. 查看 Railway 后端日志中的错误信息

## 七、生产环境优化建议

### 7.1 性能优化

**数据库优化：**
- 生产环境中，`JPA_DDL_AUTO` 可以改为 `validate`（表结构已稳定后），避免每次启动都扫描
- 根据用户量大小，适当调整 MySQL 连接池大小（在 `application-prod.yml` 中配置）

**缓存优化：**
- LLM 响应结果可以启用缓存，避免相同问题重复调用 API
- 文档解析结果缓存，避免重复处理

**静态资源：**
- Vercel 自带 CDN 和边缘缓存，前端不需要额外优化
- 如有需要，可以开启 Vercel 的 Analytics 监控页面加载速度

### 7.2 安全加固

**必须做的：**
- `APP_AUTH_SECRET` 必须是一个长随机字符串，且不在代码仓库中暴露
- `APP_CORS_ALLOWED_ORIGINS` 只允许你的正式域名，不要用 `*`
- SMTP 密码使用授权码，不是邮箱登录密码
- MySQL 密码使用强密码
- 确认 `.env` 文件没有被提交到 Git（检查 `.gitignore`）

**推荐做的：**
- 在 Railway 中启用自动 HTTPS（默认已启用）
- 定期轮换 `APP_AUTH_SECRET`（注意：轮换后所有用户需要重新登录）
- 如果有管理员功能，建议启用双因素认证（项目当前未内置，可扩展）

**检查清单：**
```bash
# 确认没有敏感文件被提交
git log --all --full-history -- "*.env" "*.env.local" ".env*"
```

### 7.3 监控与告警

**Railway 自带的监控：**
- **Metrics** 标签页：查看 CPU、内存、网络使用量
- **Deployments** 标签页：查看部署历史和日志
- Railway 会在服务崩溃时自动重启（`restartPolicyType: ON_FAILURE`）

**健康检查：**
- Railway 每隔一段时间访问 `/api/health` 检查服务状态
- 如果健康检查失败，Railway 会自动重启服务
- 建议在外部监控服务（如 [UptimeRobot](https://uptimerobot.com/)）中添加对 `https://<后端域名>/api/health` 的监控

**日志查看：**
1. 进入 Railway 后端服务页面
2. 点击 **"Deployments"** 标签页
3. 选择最新的 Deployment
4. 查看 **"Build Logs"**（构建日志）和 **"Deploy Logs"**（运行日志）

**建议的外部工具：**
- **Sentry**（可选）：接入后端和前端，收集运行时错误
- **UptimeRobot**（免费）：监控服务可用性，宕机时发邮件告警
